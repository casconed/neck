# neck

A browser editor for **Torso Electronics T-1** banks. Open a backup from the T-1 Config app, edit
patterns, tracks, cycles and steps, then download a backup zip to restore with the Config app.

> Unofficial and reverse-engineered. Not affiliated with or endorsed by Torso Electronics. Always keep
> your original backup: a malformed bank can be rejected by the device, which may re-initialise that bank.

## What it edits

- **Backups** (`.zip` from the Config app, with every bank), single **banks** (`N.t1`), and **autosaves**
  (the device's current pattern).
- **Banks:** tempo; add (copy), remove, and import patterns (including from an autosave).
- **Tracks:** notes/chords, MIDI channels, mute, copy to another pattern or slot, remove, and about
  25 settings: steps, pulses, rotate, division, repeats, time, ramp, pace, style, voicing, range, phrase,
  velocity, sustain, probability, accent, timing, delay, groove, scale, root and more. Settings shown in
  yellow are only partly decoded.
- **Cycles:** cycle count; give a cycle its own step pattern, or remove it. Stored cycles beyond the count
  are kept by the device but don't play; they're shown dimmed.
- **Steps:** click to turn a step on or off, on the base pattern and on each cycle's own pattern.
  Orange steps come from the pulse generator, blue ones were added by hand; both play.

Downloads are always backup zips. If you opened a backup, the download is that same backup with only the
edited banks replaced; every other entry is byte-identical. Restoring it overwrites all banks with what's
inside. If you opened a single bank or autosave, the download contains only that bank, and restoring it
replaces only that bank.

### Known unknowns

- The Config app's backup also contains the device's `autosave/` (a copy of the pattern that was selected
  when exporting). Whether restoring prefers that copy over an edited bank pattern is untested.
- Changing pulses, rotate or steps redraws the generated pulses, because the T-1 doesn't do it on
  load: it plays the stored steps. The redraw uses the device's own generator,
  `((step - rotate) * pulses) mod steps < pulses`, which reproduces every sample track. This
  replaces any generated pulses you removed by hand on that track; manual pulses are kept.

## Development

```bash
npm ci               # Node 22 or newer
npm run dev          # dev server at /neck/
npm test             # format tests (vitest)
npm run typecheck
npm run lint
npm run build        # static site in dist/
```

See [CONTRIBUTING.md](CONTRIBUTING.md) before opening a pull request.

The code is split in two:

- `src/format/`: pure, functional TypeScript with no React. It parses banks and autosaves, serializes them
  back byte-for-byte, and provides every edit as a function from old bytes to new bytes.
  - `track.ts`: one track block (grammar walk, settings, steps, notes, cycles)
  - `container.ts`: bank and autosave layout
  - `project.ts`: pattern and track operations
  - `zip.ts`: backup zips
- `src/components/`: React components that call those functions and nothing else.

### Tests and the reference parser

`fixtures/upstream/` holds the sample banks from
[pizboese/t1-backup-file-format](https://github.com/pizboese/t1-backup-file-format) (MIT). The tests:

- check that every sample round-trips byte for byte;
- compare the parse against that project's Python parser (`fixtures/expected/`, generated by
  `npm run oracle`), noting the places where that parser is known to be wrong;
- run every edit on every track and pattern, then re-parse the result.

`fixtures/local/` is for files from your own device. It is gitignored and tested when present.

## Deploying

The site is a Vite + React + TypeScript app. `.github/workflows/pages.yml` runs typecheck, lint, tests
and the build on every push and pull request.
It deploys `main` to GitHub Pages. To set it up:

1. In the repo's **Settings → Pages**, set **Source** to **GitHub Actions**.
2. `vite.config.ts` sets `base` to `/neck/`. If the repo has another name, change it to match.

## Credits

The track and bank format comes from Sebastian Hasinger's
[t1-backup-file-format](https://github.com/pizboese/t1-backup-file-format) (MIT): its byte map, field
offsets and samples. This project adds parsing by block grammar rather than by landmark (which handles
custom scales and the 2.1.5 bank summary), per-cycle rotate (`0x1d`) and pulses (`0x02`) override IDs,
and the structural edits.
